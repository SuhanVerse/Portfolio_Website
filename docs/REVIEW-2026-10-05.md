# Portfolio review and refinement — 5 October 2026

Scope: the live `suhankhadka.com.np` portfolio, the four supplied screenshots, current `Portfolio_Website/main` (8b855f2), homepage, all four case studies, source links, build structure and local browser behavior. The previous redesign was merged in PR #1. This review does not concern SuhanVerse.github.io.

## Why the robot appeared incomplete

The original `src/scene.js` explicitly excluded an idle animation loop. It rendered on resize, subsystem selection and a fixed-step rotation button. `src/main.js` also required an explicit click before importing Three.js. The Sense/Compute/Act buttons only changed material highlights and explanatory text. There were no sensor waves, rotating wheel groups, processing animation or automatic demonstration states. The apparent inactivity was largely an implementation choice, not evidence of a broken Three.js installation. The earlier performance compromise did not meet the requested interaction.

The updated implementation adds a four-second-per-stage Sense → Compute → Act cycle, visible scan arcs, a pulsing controller and rotating wheels. Each subsystem can be selected independently. Pause/play, auto cycle, rotate and close use keyboard-operable HTML buttons. This remains an illustrative demonstration, not live sensor data, obstacle avoidance or a physics simulation.

The viewer loads dynamically after the workbench becomes visible. Reduced-motion, Save-Data and slow connections retain manual activation; reduced-motion starts paused. Rendering is capped at 30 fps and pixel ratio 1.5, stops when offscreen or the tab is hidden, and releases resources when closed. Automatic startup does not move keyboard focus. Closing or a failed load prevents automatic reopening. Failed downloads and context loss recover the static poster.

## Prioritized additions

1. **Real demonstrations:** a short VisioBot simulation recording, actual EdumentX captures and a RoboVault API walkthrough. Use click-to-play posters; avoid loading video players during initial rendering. Add evidence links to `src/projects.mjs` and a small optional demo block to `src/templates.mjs` once genuine media exists.
2. **Individual contribution:** state what Suhan personally designed, implemented and tested for each project, including team context. Do not infer sole ownership from the repository. Add confirmed role/contribution fields to `src/projects.mjs`.
3. **Measured results:** publish reproducible robot trial results, navigation success/failure conditions, or API test results with the environment and date. Current limitations should remain until measurements support stronger claims.
4. **Résumé consistency:** reconcile the education date and update project/contribution details in `assets/cv.pdf`. No conflicting date has been guessed.
5. **Device validation:** check Safari/iOS, a mid-range Android phone and screen-reader navigation. The software-rendered Chromium checks establish functionality, not physical GPU performance or complete accessibility conformance.

Filters, more decorative backgrounds, embedded social feeds and additional libraries are low priority for four featured projects. The existing direct navigation and compact index are sufficient. Actual project evidence should be the next investment.
